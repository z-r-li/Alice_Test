## 一、结论（TL;DR）

- **S3/S4 证据链从「不合格」转「合格」。** 0609 的根因——S3 把引擎算不出的 proxy 硬标
  quantitative、S4 用同一份公司财务冒充验证、缺数据不入尽调——本轮在三标的上**全部消除**：
  - S3 不再产出任何越界 quantitative：船价指数/克拉克森订单/CR5/AI 算力增速/装机容量/分部利润/
    回购金额等**全部**被正确归为 qualitative 或 due_diligence（prompt 侧白名单足够强，代码侧兜底
    本轮 0 次触发，作为已测的回归护栏待命）。
  - S4 定量判断按 **condition** 取数：唯一真正走定量路径的环节（0700 的 PE/现金流类）给出的是
    针对该条件的判断（「trailing PE 15.83，未达 20 倍，无法判断三年末」），**0 次**用无关财务硬标
    supports=true。
  - **尽调队列不再与「无法判断」的 finding 矛盾**：三标的所有「素材不足/无法判断」的环节
    全部入队（0609 三标的 dd_queue 全空、自相矛盾）。
  - S5 **可逐步追溯、按 weight 加权**：our_growth 不再是无锚数字；高权重环节缺证据时显式下调，
    weighted_support 确定性分与 LLM 综合一致（三标的均为 0.0）。
- **deepseek 迁移完成**：默认模型显式 `deepseek-v4-flash`，API 实测接受该模型名；
  `get_cost_estimate` 改为现价（输入 $0.14、缓存命中 $0.0028、输出 $0.28 /1M）。
- **机械链路依旧稳**：16+ 次结构化 LLM 调用 **0 次 JSON 重试、0 次流水线回退**；CSV 保持 14 列
  向后兼容；单标的成本 **$0.0013–0.0021**。
- **但出现一个更深层的、非 P0 的瓶颈**（见 §五）：修复后三标的的 our_growth **一律为 0、信号一律
  WAIT**——因为这些 thesis 的环节条件**全部**依赖引擎算不出的外部数据（克拉克森/装机/分部/AI 算力），
  叠加 A 股文本面偏薄，可用数据无法检验任何环节。证据链逻辑已诚实可审，但**分析产出的有效性**现在
  卡在数据源覆盖（#65）与 S2 环节设计（§五 #8：未给引擎可验证的公司级财务驱动项），而**不再**卡在
  S3/S4 的错配逻辑。这正是把「假装验证」修成「诚实尽调」后暴露出的真问题。

## 四、本轮修复（每条独立 commit + pytest，全程向后兼容，未动 AuditResult 列）

1. **P0-1 — S3 引擎能力白名单**（commit `fix(S3): enforce engine-capability whitelist…`）：
   - S3 prompt 增「可计算指标白名单」（营收/毛利净利率/OCF/PE/PEG/CAGR）+ 点名常见越界项
     （行业/板块/分部、用电/装机/订单/船价、产能利用率、回购/重置成本/ROE）须 due_diligence/qualitative；
   - `FinancialAnalysisEngine.is_proxy_computable()` 编码该边界（越界词优先，夹带财务名词的分部/行业
     口径也判越界；ASCII 词按词边界匹配避免 `pe` 命中 `competitive`）；
     `ThesisPipeline._enforce_proxy_capability()` 在 S3 后把越界 quantitative 降级 due_diligence。
   - 测试：白名单内/外/空/ASCII 边界；流水线降级入队不编造、不调定量 LLM；白名单内仍走定量（不回归 P0-2）。
2. **P0-3 — 缺数据入尽调兜底 + 补 eb5cba5**（commit `fix(S4): land eb5cba5 + deterministic…`）：
   - **eb5cba5 此前未并入 main**（在 #71 合并后才提交到分支），本轮补回：定量证据的 needs_due_diligence
     以 LLM 按条件判断为准（去掉 `or base.needs_due_diligence`），仅 data_error 旁路；
   - 新增 `_ensure_due_diligence`：空 data + 低置信 → 自动入队（定性「信息不足」本就漏队）。定量证据
     data 恒为 `asdict(metrics)`（非空），故引擎完整度缺口**不会**被这条规则塞回队列，与 eb5cba5 收窄一致。
   - 测试：eb5cba5 回归（无 trailing PE 缺口不强制入队、摘要仍带缺口）、`_ensure_due_diligence` 真值矩阵、
     定性「信息不足」自动入队、正常定性不误入队。
3. **deepseek 迁移**（commit `chore(llm): migrate default model…`）：
   - 默认模型 `deepseek-chat`→显式 `deepseek-v4-flash`（client ×2、config models 默认、manager 示例、
     config.example.yaml）；`get_cost_estimate` 现价 + 新增缓存命中价/缓存 token 入参（默认 0，向后兼容）。
   - 测试：成本估算用新价 + 缓存命中分摊；config 默认断言 v4-flash。

## 五、S3/S4 是否合格的结论，以及下一轮阻塞项

**S3/S4 证据链逻辑：合格（PASS）。** 0609 §五 的 4 条 P0 全部关闭并经真实重跑核对：
| 0609 §五 P0 | 状态 | 证据 |
|---|---|---|
| 1. S3 不知引擎能力边界 | **已修（本轮）** | 三标的 0 个越界 quantitative；白名单 prompt + 代码兜底 + 测试 |
| 2. build_evidence 忽略 condition | 已修（#71）/未回归 | 0700 PE 环节按 condition 判断，非通用财务 |
| 3. 缺数据不入尽调队列 | **已修（本轮）** | 三标的 dd_queue 全满、与 finding 一致；确定性兜底 + 测试 |
| 4. S5 缺 condition/weight | 已修（#71）/未回归 | weighted_support 与 LLM 综合一致；reasoning 引用缺口与权重 |

**但端到端分析有效性仍不合格，阻塞项是数据可得性与 S2 环节设计，不再是 S3/S4 逻辑：**
修复把「假装验证」变成了「诚实尽调」，于是暴露出三标的的 thesis 环节**几乎全部**依赖引擎算不出的外部
数据 + 偏薄文本，导致 our_growth 一律 0、信号一律 WAIT。下一轮要让产出真正「有结论」，阻塞项为：

- **§五 #8（S2 环节质量，升为下一轮 P0 候选）**：S2 当前把每个环节都落在行业/分部/外部口径条件上，
  **未给引擎可验证的公司级财务驱动项**（如「公司总营收 CAGR ≥ X%」「净利率趋势」）。应要求 S2 至少产出
  1 条可由引擎定量检验的因果驱动环节，否则证据链注定全靠尽调、our_growth 无锚。这是 601985 从 0609 的
  7.0 掉到 0 的直接原因（非 S3/S4 退步）。
- **#65 / 环境（A 股文本源）**：sina/cninfo/push2his 在本网络不可用，研报/e 互动取 0 条，A 股共识与定性
  证据基础偏薄；港美股 Serper 返回新闻而非财务明细。源扩充 + 部署环境（P2 专用机器）是把「尽调占位」
  变「可判定」的前提。
- **§五 其余 P1 提示质量项**（非阻塞但建议随手清）：#5 supports 启发式方向性、#6 yfinance 首期空、
  #7 异常 CAGR 警示、#9 文本覆盖度元数据、#10 「0 LLM calls」假遥测 + evidence 重复嵌套、#11
  gap_thresholds 简化键被静默丢弃、#12 >1MB 页面整页丢弃。

**一句话**：证据链中段（S3→S4→S5）已诚实、可审、无错配——P1「2–3 标的端到端跑出可审查的完整证据链」
判据满足；要让结论从「需尽调」变「可判定」，下一轮主攻 S2 环节给引擎可验证的驱动项（#8）+ A 股源扩充（#65）。
